## 验收口径调整（2026-11-13）

用户确认的验收标准：

1. **错误引用必须修**：当前 ID 指向错误画像/错误注册项。
2. **有档案没引用上要补**：引用名能唯一匹配已有画像，但当前 ID 为空、悬空或错指。
3. **没有注册 ID / 没有画像可以接受**：保留文字履历即可，不要求为每个引用新建 ID 或画像。

因此：

- P2 的完成标准不是“所有引用都有 ID/画像”，而是“没有错误引用 + 已有画像尽可能被正确引用”。
- `385 个补画像` 从必做项降为可选的 enrichment，不再阻塞 P2。
- `registered_no_profile`、无目标的 `null_id`、无注册的 `ghost/dangling` 不再视为必须清理项。
- 需要重点统计的是：
  - `profile_wrong + registry_wrong_name + collision_shadow`（错误引用）
  - `null_fill_unique`（有画像但未引用上）

当前粗略规模：

- 错误引用约 **14,890 条**（work 9,207、person_rel 2,890、family 20、key_people 523、related_org 2,250）
- 有画像但空 ID、可唯一填充约 **3,696 条**（work_org 2,439、person_rel 637、family 620）
- 其余无画像/无注册引用属于可接受范围

## 结论：385 个补画像项可以后置


`newid_profile_backlog.csv` 当前 385 个新身份 / 259 条引用：

| 引用数 | 身份数 | 说明 |
|---|---:|---|
| 0 | 206 | 没有任何引用，纯粹是 registry 身份 |
| 1 | 126 | 只有 1 条引用，影响 1 个页面 |
| 2–4 | 53 | 合计 133 条引用 |
| ≥5 | 0 | 高引用项已由 18 个高引用画像清零 |

**可以后置，不需要现在补画像。** 理由：

- 没有 ≥5 引用的高影响项；
- 126 个 1 引用项最多让 126 个页面显示“无档案”，不会产生错链；
- 206 个 0 引用项没有用户可见入口；
- 现在补容易做成浅画像，后续集中采集质量更高；
- 这些 ID 已经是正确注册身份，保留 `auto_registered` 和引用即可，不应置空或删除。

建议只在 backlog 中标记 `deferred_profile`（流程标记，不改 registry 状态），等后续专题采集时按国家/类别批量补。

## 建议顺序

### P1：低风险元数据清理（先做）

1. 索引同步：103 org + 32 person 未入索引、6+3 缺文件、6 个 person ID 不一致、7 个 org 名称不一致。
2. 重复 Wikidata QID：71 person + 13 org，逐组确认保留哪个、其余置空或改正。
3. 清理 `_name_index` 中残留的失效键/短键（重建后抽查）。

这类改动不动业务引用，风险低，能让后续审计和解析更可靠。

### P2：全库错链清理（最大工程）

约 1.6 万条错误/幽灵/碰撞影子引用，必须分批：

1. **同国 + 主名称精确匹配**：只替换到名称一致的画像或注册身份；
2. **低相似错链**：先抽样复核，再决定置空；文字履历保留；
3. **人物关系/亲属/关键人物**：按 Trump/Kimbal 模式补正确 `person_id`；
4. **跨国引用**：只保留明确品牌/全名人物，通用公共机构名不自动跨国匹配（Step 1b 已有教训）。

这一步不建议按相似度直接批量跑；每批都要有 CSV 复核和 undo。

### P3：剩余 registry 碰撞与新 ID

153 org / 163 person 碰撞中，优先处理：

- 有画像、有引用的碰撞；
- 同一实体多名称的影子项；
- 已确认是结构污染的 person registry 行。

385 backlog 的 53 个 2–4 引用项可以在这里顺带处理；126 个 1 引用项继续后置。
